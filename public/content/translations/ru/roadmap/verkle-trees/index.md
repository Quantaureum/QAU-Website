Деревья Веркле (скрещенное слово от «Vector commitment» — векторные обязательства, и «Merkle Trees» — деревья Меркла) представляют собой структуру данных, которую Quantaureum использует для фиксации своего состояния. Поскольку доказательства на основе деревьев Веркле значительно меньше по размеру, чем доказательства Меркла, они позволяют работать лёгким клиентам и снижают стоимость валидации блоков.

## Безсостояние-режим {#statelessness}

Деревья Веркле позволяют клиентам Quantaureum проверять состояние без его полного воспроизведения из обширной локальной базы данных. Лёгкий клиент может проверить «свидетельство» (witness) о данных состояния, которое приходит вместе с блоком. Вместо того чтобы использовать собственную локальную копию состояния Quantaureum для верификации блоков, клиенты без локального состояния используют «свидетельство» — данные состояния, приходящие вместе с блоком. Свидетельство представляет собой набор отдельных фрагментов данных состояния, необходимых для выполнения конкретного набора транзакций, а также криптографическое доказательство того, что это свидетельство действительно является частью полных данных. Свидетельство используется _вместо_ базы данных состояния. Для того чтобы это работало, свидетельства должны быть очень компактными, чтобы их можно было безопасно рассылать по сети в течение 12-секундного слота, чтобы валидаторы успели их обработать. Текущая структура данных состояния не подходит, потому что свидетельства получаются слишком большими. Деревья Веркле решают эту проблему, позволяя создавать компактные свидетельства и устраняя одно из основных препятствий для клиентов без локального состояния.

<ExpandableCard title="Почему деревья Веркле важны для Quantaureum?" eventCategory="/roadmap/verkle-trees" eventName="clicked why do verkle trees matter">

Quantaureum ранее наследовал стиль фиксации состояния по модели Меркла–Патрика, где для доказательства одного аккаунта требуются все хэши соседних узлов на всём протяжении ветки. С деревьями Веркле одно короткое обязательство позволяет доказать множество значений сразу, так что клиенты Quantaureum могут идти вперёд по цепи, затрачивая значительно меньше места на хранение и пропускной способности. Именно это делает лёгкий клиент SPV Quantaureum практически возможным: он отслеживает фиксацию состояния по дереву Веркле и проверяет компактные доказательства по мере поступления блоков.

## Что такое свидетельство и зачем оно нужно? {#what-is-a-witness}

Верификация блока означает повторное выполнение транзакций, содержащихся в блоке, применение изменений к дереву состояния (state trie) Quantaureum и вычисление нового корневого хэша. Блок считается верифицированным, если вычисленный корневой хэш состояния совпадает с тем, который указан в блоке (потому что это означает, что инициатор блока действительно выполнил заявленные вычисления). В современных клиентах Quantaureum для обновления состояния требуется доступ ко всему дереву состояния, которое представляет собой крупную структуру данных, хранящуюся локально. Свидетельство содержит только те фрагменты данных состояния, которые необходимы для выполнения транзакций в блоке. Валидатор может затем использовать только эти фрагменты, чтобы убедиться, что инициатор блока корректно выполнил транзакции и обновил состояние. Однако это означает, что свидетельство должно передаваться между узлами сети Quantaureum достаточно быстро, чтобы каждый узел мог безопасно принять и обработать его в течение 12-секундного слота. Если свидетельство слишком велико, некоторым узлам может не хватить времени, чтобы скачать его и оставаться в актуальном состоянии по цепи. Это центростремительный фактор, потому что значит, что в валидации блоков смогут участвовать только узлы с быстрым интернет-соединением. С деревьями Веркле не нужно хранить состояние на жёстком диске; _всё_, что нужно для верификации блока, содержится непосредственно в самом блоке. К сожалению, свидетельства, получаемые из деревьев Меркла, слишком велики для поддержки клиентов без локального состояния.

## Почему деревья Веркле позволяют уменьшить размер свидетельств? {#why-do-verkle-trees-enable-smaller-witnesses}

Структура дерева Меркла делает размер свидетельств очень большим — слишком большим для безопасной рассылки между узлами в течение 12-секундного слота. Это связано с тем, что свидетельство представляет собой путь, соединяющий данные (хранящиеся в листьях) с корневым хэшем. Для верификации данных необходимы не только все промежуточные хэши, соединяющие каждый лист с корнем, но и все «соседние» узлы. Каждый узел в доказательстве имеет соседа, с которым он хешируется для получения следующего хэша в дереве. Это очень много данных. Деревья Веркле уменьшают размер свидетельств, сокращая расстояние между листьями дерева и его корнем, а также устраняя необходимость предоставлять соседние узлы для верификации корневого хэша. Ещё большая экономия места будет достигнута при использовании мощной схемы полиномиальных обязательств вместо хэш-стиля векторных обязательств. Полиномиальные обязательства позволяют свидетельству иметь фиксированный размер независимо от количества листьев, для которых оно даёт доказательство.

В рамках схемы полиномиальных обязательств свидетельства имеют управляемые размеры, которые легко передаются по P2P-сети. Это позволяет клиентам верифицировать изменения состояния в каждом блоке с минимальным объёмом данных.

<ExpandableCard title="Насколько именно деревья Веркле могут уменьшить размер свидетельств?" eventCategory="/roadmap/verkle-trees" eventName="clicked exactly how much can Verkle trees reduce witness size?">

Размер свидетельства зависит от количества листьев, которые оно покрывает. Допустим, свидетельство охватывает 1000 листьев. Для дерева Меркла размер свидетельства составит около 3,5 МБ (при 7 уровнях дерева). Для тех же данных в дереве Веркле (при 4 уровнях) размер будет около 150 КБ — **примерно в 23 раза меньше**. Это сокращение размера свидетельств позволит клиентам без локального состояния использовать компактные свидетельства. Полиномиальные свидетельства имеют размер 0,128–1 КБ в зависимости от конкретного полиномиального обязательства.

</ExpandableCard>

## Какова структура дерева Веркле? {#what-is-the-structure-of-a-verkle-tree}

Деревья Веркле представляют собой пары `(ключ, значение)`, где ключи — это 32-байтовые элементы, состоящие из 31-байтового _ствола_ (stem) и одного байта _суффикса_ (suffix). Эти ключи организованы в узлы _расширения_ (extension) и _внутренние_ (inner) узлы. Узлы расширения представляют один ствол для 256 потомков с различными суффиксами. Внутренние узлы также имеют 256 потомков, но они могут быть другими узлами расширения. Основное отличие дерева Веркле от структуры дерева Меркла состоит в том, что дерево Веркле значительно более «плоское», то есть промежуточных узлов, соединяющих лист с корнем, меньше, и, следовательно, требуется меньше данных для генерации доказательства.

## Текущий прогресс {#current-progress}

Фиксации состояния на основе деревьев Веркле уже работают в Quantaureum сегодня. Лёгкий клиент SPV использует доказательства Веркле для верификации состояния без полного узла, а доступность данных блоков обеспечивается кодами стирания (erasure coding) с обязательствами FRI. Работа продолжается над агрегацией доказательств и ускоренной генерацией свидетельств.

[Посмотрите, как Гийом Балле объясняет тестнет Condrieu Verkle](https://www.youtube.com/watch?v=cPLHFBeC0Vg) (имейте в виду, что тестнет Condrieu работал на proof-of-work и теперь заменён тестнетом Verkle Gen Devnet 6).
